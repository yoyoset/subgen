# subgen 用户体验评审(2026-07-23)

> 评审角色:只使用软件、不了解内部实现的普通用户体验评审人。只关注用户通过界面、提示、可配置项能感知到的部分,不评价架构/性能/容错本身。所有场景基于界面上真实存在的文案和交互。

## 1. 系统透明度

### 1.1 "提取音轨"阶段没有任何进度
- 场景:拖进 2 小时电影,状态停在"正在提取音轨...(已运行 45秒)",无百分比。
- 本质:用户不知道这步"正常应该多快",30 秒没动就怀疑卡死——而这是流程第一步,第一印象就是"是不是不动了"。
- 改法:不定进度动画(egui Spinner)+ 文案"正在读取视频音轨,通常不到一分钟"。预期时长比精确百分比更重要。

### 1.2 识别有百分比却没有"还要多久"
- 场景:"正在识别语音... 42%(已运行 3分12秒)"。用户想知道"能不能去泡杯茶"。
- 改法:百分比 >5% 后追加"约剩 4 分钟"(已运行/进度 线性外推)。首条进度出现前文案改"正在识别语音(大文件可能 1~2 分钟后才显示进度)"。

### 1.3 没有批次级总进度
- 场景:排 20 集,切到别的窗口干活,想瞄总进展只能切回来逐行看。
- 改法:顶部总进度("第 3/20 个文件,总进度约 14%"),百分比写进窗口标题(`字幕生成器 [3/20]`),任务栏悬停可见。

### 1.4 "正在启动本地翻译引擎..."最长可挂 3 分钟,无进度无解释
- 场景:首次勾选翻译,翻译阶段界面停在这行一分多钟。
- 本质:用户不知道"启动引擎"是在往显卡装 4GB 的东西,只觉得"翻译卡住了"。
- 改法:"正在加载翻译模型(文件较大,首次约需 1 分钟)…"+ Spinner。

### 1.5 下载页面列组件名,不列大小
- 场景:首次启动看到组件名和"开始下载",点下去才发现按 GB 计。
- 本质:用户在不知情下做了"可能半小时 + 10GB 流量"的决定;磁盘警告只在不够时出现。
- 改法:每项标大小,底部"共需下载约 7.9 GB,只需下载这一次"。

## 2. 黑盒决策

### 2.1 自动检测出的语言从不展示(本维度最重要之一)
- 场景:语言选 auto,某集被误检成韩语,翻译一塌糊涂。用户只看到"完成"和烂译文,没有任何线索指向"语言检测错了",更不知道手动指定语言就能修好。
- 改法:完成状态显示"识别语言: 日语(自动检测)";开翻译时同时显示所用模型。检测置信度低时提示"语言检测把握不大,若结果异常请手动指定语言"。

### 2.2 "自动(按视频语言选择)"选了什么,事后无从知道
- 改法:完成行显示"翻译: Sakura(日→中)"。只回显,不需要能改。

### 2.3 复用上次结果(缓存)对用户完全隐形(最危险的黑盒)
- 场景:用户删掉不满意的 srt、换个模型重跑——秒完成,内容一模一样(缓存复用,且缓存不区分模型,换模型后依然命中旧结果)。
- 本质:用户视角是"我改了设置,软件骗我说做完了,但什么都没变",直接摧毁信任。
- 改法:① 完成提示保留复用痕迹"完成(复用了上次的识别结果)";② 每行提供"重新处理(不使用上次结果)";③ 换模型后旧缓存不应命中。

### 2.4 部分行翻译失败的提示是内部术语
- 场景:"翻译中有 3 行未能对齐,已保留原文"——"对齐"是内部概念,且不知道是哪 3 行。
- 改法:"有 3 行翻译失败,已保留原文(第 45、112、113 条)"。

## 3. 掌控感与可逆性

### 3.1 点"取消"后没有任何反馈
- 场景:翻译中点"取消",按钮和状态纹丝不动,可能一两分钟后才真的停。用户连点、怀疑按钮坏了、直接关窗。
- 改法:点击瞬间按钮变灰显示"正在取消…",当前任务状态行变"正在取消,等待当前步骤结束…"。停不下来没关系,让用户知道指令已收到。

### 3.2 取消会丢进度,且事先不告知
- 场景:识别到 80% 取消,重跑从 0% 开始。
- 本质:用户对"取消"的直觉是"暂停/中止在当前位置",不是"作废重来";崩溃反而能接上,主动取消却清零,反直觉。
- 改法:至少告知"当前文件已完成的部分将丢弃";更好:保留已提取的音轨。

### 3.3 处理中设置项看起来能改,实际不生效
- 场景:跑着任务改模型/语言,界面全部接受并保存,本批无感。
- 改法:处理中禁用这排控件,或旁注"处理中,修改将从下一次开始生效"。

### 3.4 "清空列表"在处理中点了毫无反应
- 场景:按钮外观正常可按,点击静默无效。
- 改法:处理中直接置灰禁用(与"开始处理"一致)。

### 3.5 处理中拖入文件被静默吞掉
- 改法:允许入队(状态"等待中")或当场提示"正在处理中,请稍后再添加"。静默无视是最差选择。

### 3.6 处理中关窗没有确认(损失最大的单点)
- 场景:批量任务跑 50 分钟,误点右上角 ×,全部立即终止,无挽回。
- 改法:处理中拦截关闭,弹"正在处理第 3/20 个文件,退出将中止处理。确定退出?"。

### 3.7 无法对单个文件做任何操作
- 场景:10 个文件里 1 个拖错/1 个想重跑,唯一操作是"清空列表"全部重来;已完成的更是锁死。
- 改法:每行悬停小按钮或右键菜单:移除、重新处理、打开所在文件夹、打开字幕。

## 4. 信任校准

### 4.1 空字幕也叫"完成"
- 场景:纯音乐视频跑完绿色"完成",播放器里加载不出字幕,用户结论:软件坏了。
- 改法:"完成(未检测到对白,字幕为空)"。

### 4.2 "建议抽查该片段"却不说是哪个片段
- 场景:"检测到疑似复读故障已自动折叠,建议抽查该片段"——45 分钟视频去哪抽查?"复读故障""折叠"也是黑话。
- 改法:"在 08:06 附近检测到异常重复内容,已自动修正,建议播放核对该处"。

### 4.3 所有成功一律绿色"完成",没有质量分层
- 场景:20 集跑完,1 集其实置信度低/失败 30 行,列表里长得几乎一样。用户要么全部人工核对,要么全部不看——软件没把注意力引向真正需要看的那集。
- 改法:结束汇总"20 个完成,其中 2 个建议人工核对(点击查看)",DoneWithWarning 聚合置顶。

### 4.4 验证质量必须离开软件
- 改法:完成行可展开前 5~10 条"原文/译文"对照,只读预览,10 秒建立质量判断。

## 5. 新手自解释性(没读过 README 的人)

### 5.1 首次下载清单是开发者词汇
- 场景:"识别引擎 (whisper.cpp)""FFmpeg (音频提取)""语音活动检测模型""本地翻译引擎 (llama.cpp)"。
- 本质:全是零信息量外语;页面也没回答新手三问:要下多大?下几次?视频会不会被传出去?
- 改法:用途导向文案("语音识别组件"等,技术名放括号小字);底部加:"以上组件仅首次使用时下载一次,全部在你自己的电脑上运行,视频和字幕不会上传到任何服务器。"——这也是软件最大卖点,目前只写在 README。

### 5.2 语言下拉框是 ISO 代码
- 改法:显示"自动检测/中文/英语/日语/韩语/法语/德语/西班牙语",内部值不变。

### 5.3 模型选项用显卡型号和倍速描述
- 场景:"large-v3 - 最准确(推荐,3060 上约 8 倍实时速度)"。
- 改法:"标准(最准确,推荐)/ 快速(准确率略降)/ 极速(适合配置较低的电脑)"。

### 5.4 "生成中文翻译(本地模型)"暴露实现细节
- 改法:"翻译成中文(在本机完成,不上传内容)"。

### 5.5 GPU 警告给出的行动不可执行
- 场景:"请检查显卡驱动 / CUDA 环境"——普通用户不知道 CUDA 是什么。
- 改法:"⚠ 未能使用显卡加速,处理会慢很多。请到 NVIDIA 官网更新显卡驱动后重试;如果这台电脑没有 NVIDIA 显卡,只能使用较慢的模式。"

### 5.6 失败时把引擎原始日志直接铺在界面上
- 场景:"识别引擎返回错误(退出码: -1073741819(十六进制 0xc0000005),详见日志 …):"后跟 15 行英文引擎输出,撑爆行高。
- 本质:成品感崩塌最严重的瞬间,用户唯一能做的是拍照求助。
- 改法:一行人话("识别失败,可能是文件损坏或显存不足")+ "重试" + "查看详细日志"(记事本打开日志)。技术细节留在日志,不进列表。

## 6. "像不像一个完成品"

- **窗口/exe 无图标**:默认白块是"能跑的脚本"第一视觉信号。加图标对成品感提升不成比例地大。
- **无版本号**:标题栏加"subgen 0.1",用户反馈问题才说得清版本。
- **标点与文案不统一**:半角/全角混用("完成,但有提示:");"跳过: 已存在同名字幕,已跳过: C:\长路径"一句两个"跳过"+裸路径。统一全角标点,路径只显示文件名(完整路径悬停)。
- **下载/搬迁页日志区是原始流水**:默认收起为"详细信息 ▸"折叠。
- **错误红色多行文本直接铺开**:行高不可控,单个失败项破坏整个列表观感(见 5.6)。
- 目前观感是"工程师给自己做的趁手工具",离"成品"隔的不是功能,正是这一层。

## 按"用户感知提升 / 投入比"排序的优先级

| # | 事项 | 一句话理由 |
|---|------|-----------|
| 1 | 处理中关窗加确认弹窗 | 唯一会造成"一小时白干"的灾难点,几行代码 |
| 2 | 取消的即时反馈("正在取消…")+ 丢进度告知 | 按钮无反应是最强烈的"软件坏了"信号 |
| 3 | 错误提示人话化:一行摘要 + "查看日志"按钮 | 失败时刻是信任的决胜局,现在是最差表现 |
| 4 | 缓存复用可见化 + "重新处理"入口(换模型必须真生效) | 修复"改设置没用"这个信任杀手 |
| 5 | 完成状态分层:空字幕说明、复读警告带时间戳、失败行号、批次汇总 | 让用户知道"哪些要看、哪些可以放心" |
| 6 | 回显自动决策:检测到的语言 + 实际用的翻译模型 | 结果不好时用户第一次有了自查线索 |
| 7 | 批次总进度 + 剩余时间估计 + 窗口标题进度 | 长任务工具的"能不能安心切走"问题 |
| 8 | 首次下载页:标大小、"只下一次"、"不上传视频"三句话 | 新手第一分钟的信任建立,也是卖点前置 |
| 9 | 术语人话化:语言名、模型档位、翻译开关、GPU 警告 | 纯文案改动,零逻辑风险 |
| 10 | 处理中控件的诚实状态:禁用清空/设置,拖拽给反馈 | 消灭"点了没反应"类假活跃 |
| 11 | 单文件操作:移除/重跑/打开文件夹/预览前几条 | 掌控感从"批次"细化到"文件" |
| 12 | 图标 + 版本号 + 标点统一 + 日志折叠 | 纯观感,但决定第一印象的档次 |
