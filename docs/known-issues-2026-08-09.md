# 已知但暂不处理的问题(2026-08-09 记录)

> 原则:明知但暂不处理的问题显式列出来,写明原因,不许悄悄消失。
> 每一条都是本轮 UX 走查时发现的真实行为,不是臆测。

## 1. 已有原文字幕 + 开启翻译 + 不覆盖 → 整个任务跳过,连翻译也不做

**真实行为**(读代码确认,非回归,我的 "跳过判定提前" 改动前后行为一致):

用户已经有 `Video.srt`(比如上一季没开翻译跑出来的),现在勾选"翻译成中文",
`overwrite_existing = false`(默认)。点"开始处理":

1. `job::run_batch` 在开工前用 `existing_srt_skip_reason` 判定 `Video.srt` 已存在
   → 任务直接标记为 `Skipped("已有同名字幕,未覆盖(...)")`。
2. 翻译阶段根本没有机会运行,用户拿不到 `Video.zh.srt`。

**为什么这是问题**:用户的意图是"我已经有字幕了,只想让它被翻译成中文",但得到的是
"跳过: 已有同名字幕",而且这行文案完全没解释"因为原文被跳过,所以翻译也没做"——
用户会以为翻译功能坏了,或者干脆没意识到要先把原文删掉/改覆盖设置。

**为什么暂不处理**:

- 修复方向不是改文案,而是改流程:跳过原文字幕时,应该直接拿**已存在的** `Video.srt`
  当输入跑翻译(不需要重新跑 ffmpeg/whisper,反正原文已经有了)。这要求把 `run_batch`
  里"process_video → place_sidecar_srt → translate"这条线性流程改成可分支的,`placed`
  的来源有两种(新生成的 / 已存在的),并且跳过原文字幕时仍然要把已存在的原文路径传给
  translate 阶段。
- 这个分支会引入一个新的"结果来源"状态(`detected_language`/`subtitle_count`/`reused_srt`
  等 report 字段在"没跑 process_video"时怎么填),需要额外设计,不是几行的事。
- 翻译相关的任何流程改动,按项目纪律都要拿真实模型跑一遍确认没引入质量回归
  (见 README TODO 里"翻译跨批上下文携带"的同款要求)。当前没有真实模型环境可验证。

**如果以后要修**:先写单测覆盖"已有原文 + 开翻译 → 用已有原文翻译、产出 .zh.srt、原文
不被覆盖"这条路径,再改 `run_batch` 的分支逻辑。
