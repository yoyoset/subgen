# subgen 合并执行方案(2026-07-23)

> 由两轮独立评审(docs/review-2026-07-23-技术评审.md、docs/review-2026-07-23-用户体验评审.md)合并而成。配对与定位基于当日源码的实际阅读,文中行号以当日代码为准。

## 一、配对清单

每组是"同一处代码改动被两个视角各描述一次",必须作为一次改动实施。⚠ = **必须先改后端逻辑才能诚实展示**,只加提示文字有害。

- **配对① ⚠ 缓存/断点续跑正确性与可见化** = 技【断点续跑语言恢复偏差】+ 体【2.3 缓存复用隐形】+ 体【3.7 重新处理入口】。
  理由:三条都落在 engine.rs:100 的缓存键 `unique = format!("{stem}_{:x}", simple_hash(path))`——缓存键不含模型和语言,"换模型重跑结果不变"是缓存逻辑真的错了。只加"已复用"提示等于宣告软件在骗人。先把 model_key+language 纳入哈希,再展示复用状态,再提供绕过缓存的"重新处理"。语言恢复偏差同链顺修。
- **配对② ⚠ 翻译失败行** = 技【双语失败行输出两遍原文】+ 体【2.4 "未能对齐"术语+不知哪几行】。
  理由:同一返回值改造。translate.rs:291 `translate_batch_with_retry` 改返回失败行号集合,同时解决双语重复 bug 与"第 45、112 条失败"的展示。
- **配对③ ⚠ 取消语义** = 技【取消删 wav】+ 体【3.2 丢进度不告知】+ 体【3.1 取消无反馈】。
  理由:正确做法不是告知丢进度,是别丢——engine.rs:270-276 取消路径保留 wav,再配"正在取消…"按钮反馈。
- **配对④ ⚠ 翻译阶段 GPU 检测** = 技【llama-server 日志只排空】+ 体【5.5 GPU 警告不可执行】。
  理由:翻译阶段根本没有检测(translate.rs:148-157 排空线程),文案再好无从触发。先解析 offload 行接入 GpuMissing,再重写文案。
- **配对⑤ 终态信息回显管道** = 体【2.1 检测语言不显示】+ 体【2.2 所用模型不显示】+ 体【4.1 空字幕叫完成】+ 体【4.2 复读无时间戳】。
  理由:同一件事——JobStatus::Done 是无字段变体,数据在终点前被扔掉。Done/DoneWithWarning 携带小结构(语言/模型/条数/复读时间戳),collapse_repetitions 返回 Option<时间戳>。属"先通数据、再展示"。
- **配对⑥ 日志体系** = 技【持久化 app.log】+ 体【5.6 日志直出界面】+ 体【6 日志折叠】。
  理由:"查看日志"按钮的前提是日志持久完整;错误状态行一行化(engine.rs:301-310)+ 按钮 + log_lines 落盘,一次改造。
- **配对⑦ 批次汇总与结束提醒** = 技【批次汇总】+ 技【任务栏闪烁】+ 体【4.3 无质量分层】。
  理由:实现同一:BatchDone 聚合 JobStatus(依赖配对⑤的信息化状态)+ RequestUserAttention 同触发点。
- **配对⑧ 每行操作与预览** = 技【打开文件夹】+ 技【预览】+ 体【3.7 单文件操作】+ 体【4.4 预览】+ 体【3.5 处理中拖入排队】。
  理由:全落在任务列表行同一次交互改造;"重新处理"依赖配对①。
- **配对⑨ 总进度可见** = 技【任务栏 COM 进度】+ 体【1.3 总进度/窗口标题】:同一诉求两档实现。
- **配对⑩ 版本号** = 技【标题栏版本】+ 体【6 无版本】:同一行代码。
- **配对⑪ 首次下载页** = 体【1.5 不列大小】+ 体【5.1 术语+新手三问】:同一页面文案改造,数据(estimated_size_bytes)已有;与断点续传/镜像(后端)同阶段不同改动。

## 二、分类结果

**A0 · 纯后端底座**(无展示层,阻塞/保护一切后续):git 首次提交、ffmpeg 固定版本+哈希、渲染器切 Glow、fs4 单实例锁、cache_prompt 一行、下载断点续传、镜像回退。

**A · 缝合类**:配对①⚠、②⚠、③⚠、④⚠、⑤、⑥、⑦;小件:配置损坏提示。

**B · 零成本体验类**:关窗确认、取消按钮反馈、处理中禁用设置/清空、拖拽被拒提示、ETA+等待文案(1.1/1.2/1.4)、语言/模型/翻译开关/GPU 警告文案人话化、标点统一、日志区折叠、下载页大小与三句话、窗口标题进度、图标+版本号。

**C · 新设计类**:每行操作+只读预览、ass 输出+排版后处理、显存降级、跨批上下文提示词、术语表、tmp/logs 清理、Vulkan 后端、任务栏 COM 进度、Sakura A/B、SmartScreen 文档。

## 三、分阶段执行方案

排序依据:先消灭"会烧起来/污染调试"的,再做"其余展示都依赖的数据管道",再收低垂果实,最后新设计。

### 阶段 0:底座(约 1 天)
- **0-1 git 首次提交**。10 分钟。不做:任何改坏无法回退。
- **0-2 ffmpeg 固定版本+哈希**。setup.rs 顶部常量区。1~2 小时。不做:上游一变所有新用户首启失败。
- **0-3 渲染器切 Glow**。main.rs NativeOptions 加 `renderer: Renderer::Glow`(确认 eframe 0.35 glow feature)。0.5~2 小时。不做:已发生过的 wgpu 设备丢失 panic 随时复发。
- **0-4 单实例锁**。main() 起始 fs4 锁 `app_dir()/subgen.lock`,失败 rfd 弹窗退出。1~2 小时。不做:双开抢端口、互踩缓存、误导性报错。

### 阶段 1:状态管道诚实化(2~3 天,核心;共享 EngineOutcome→translate 返回值→JobStatus→UI 渲染一条链)
- **1-1 ⚠ 缓存键修正+复用可见化(配对①)**:哈希输入加 model_key+language;EngineOutcome 加 reused 标记;语言未知带标记。UI:完成附"(复用了上次的识别结果)"、语言未知警告。半天~1 天。不做:换模型重跑无效,"设置是摆设"——头号信任杀手。
- **1-2 ⚠ 翻译失败行(配对②)**:返回失败行号(跨批加偏移);双语拼接失败行只出一遍原文。UI:"有 N 行翻译失败(第 45、112 条)"。2~4 小时。不做:双语字幕原文重复两行;术语困惑。
- **1-3 ⚠ 取消语义(配对③)**:取消保留 wav 只删半成品 srt;UI 按钮"正在取消…"置灰+状态行同步。2~3 小时。不做:取消比崩溃损失大;按钮无反馈致连点/关窗。
- **1-4 终态信息回显(配对⑤)**:Done/DoneWithWarning 携带 {detected_lang, trans_model, subtitle_count, repetition_at};collapse_repetitions 返时间戳;空字幕带标记。UI:"完成 · 日语 · Sakura"/"完成(未检测到对白)"/"在 08:06 附近"。1 天。不做:结果差时无自查线索;空字幕被当故障。
- **1-5 日志体系(配对⑥)**:错误一行摘要+全文进日志;log_lines 落盘 app.log。UI:"查看日志"按钮;下载/迁移页日志折叠。半天。不做:失败时刻一屏英文日志;远程排障无现场。

### 阶段 2:安装链路(1~2 天)
- **2-1 下载断点续传**:setup.rs:582 附近,.part + Range 续传,哈希照旧。半天~1 天。不做:4GB 下载失败从零重来,新用户首屏流失。
- **2-2 镜像回退**(面向大陆则必做):官方失败自动试 hf-mirror/代理前缀,日志提示已切换。半天。不做:大陆用户卡死第一步。
- **2-3 下载页文案(配对⑪)**:组件名用途化、标大小、"共约 X GB,只下一次,不上传视频"。1~2 小时。不做:新手不知情做 10GB 决定;隐私卖点从未出现在界面。

### 阶段 3:B 类闪电战(约 1~1.5 天,可与任何阶段并行)
- **3-1 交互诚实四件套**:关窗确认(close_requested+CancelClose)、处理中禁用设置/清空(add_enabled)、拖拽被拒提示。半天。不做:误点 × 一小时白干;假活跃控件持续制造"软件坏了"印象。
- **3-2 等待期体验**:提取 Spinner+预期文案;识别 ETA(started_at+pct 外推);翻译模型加载说明。2~3 小时。不做:每个长停顿被解读为卡死。
- **3-3 全量文案过一遍**:语言中文名、模型档位、翻译开关、GPU 警告、标点、路径截断。2~3 小时。不做:每个术语都是新手卡壳点。
- **3-4 图标+版本号+窗口标题进度**。2~3 小时。不做:任务栏白块即"半成品"第一印象。

### 阶段 4:翻译质量与性能可见性(2~3 天)
- **4-1 ⚠ 翻译 GPU 检测(配对④)**:排空线程解析 offload/CUDA 行发 GpuMissing;搭车 cache_prompt:true。UI 警告分阶段+人话化。半天。不做:翻译静默掉 CPU→超时重试雪崩,用户只觉得"翻译慢"。
- **4-2 跨批上下文携带**:build_prompt 附前批末 2~3 行原文+译文作上下文。半天+真实视频验证。不做:人称/译名在批边界持续漂移——当前翻译质量最便宜的显著提升点。

### 阶段 5:新设计类(按需排期,每项先过简短设计)
- **5-1 批次汇总+结束提醒(配对⑦)**:BatchDone 聚合"18 完成/2 建议核对/1 失败"+警告置顶+RequestUserAttention。半天~1 天。
- **5-2 每行操作+只读预览(配对⑧)**:移除/重新处理(依赖 1-1)/打开文件夹/展开前 10 条;处理中拖入改排队。1~2 天。
- **5-3 ass 输出+排版后处理**:断行/最短时长/双语大小字。需设计讨论。2~3 天。
- **5-4 显存探测+低显存串行降级**:需设计讨论(阈值/探测/提示)。
- **5-5 其余**:术语表、tmp/logs 清理、Vulkan、Sakura A/B、SmartScreen 文档、任务栏 COM 进度。

**明确搁置**:流水线并行提取、超长文件分段、翻译目标语言可配、自动更新。

## 四、总结

若只做前三项(阶段 0/1/2):软件"变漂亮"的程度有限,但新用户首次安装成功率、失败时刻的可自救性、以及"软件不会骗我"这三件决定用户留下还是删掉的事,会一次性从最薄弱提到合格线以上——消灭全部四个信任杀手级缺陷(缓存欺骗、失败行 bug、取消坑人、日志天书)和两个最大流失点(下载失败、崩溃无保护);其余阶段解决"更好用",这三项解决"敢不敢用"。
